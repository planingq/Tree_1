# جذور — شجرة العائلة التفاعلية

إصدار MVP عربي باتجاه RTL، يعمل محليًا داخل المتصفح. بُني على React وTypeScript وVite وTailwind CSS وReact Flow، مع تخطيط مدمج يحافظ على تجاور الإخوة. جميع الأسماء التجريبية خيالية.

## التشغيل

المتطلبات: Node.js 22.12 أو أحدث (اختُبر على Node 24)، وnpm.

```bash
npm install
npm run dev
```

افتح عنوان خادم Vite الذي يظهر في الطرفية. لا توجد مفاتيح سرية أو خدمة خارجية مطلوبة. اختر «مدير» أو «مشاهد» في شاشة الدخول التجريبية. اختيار الدور يقيّد أدوات الواجهة لأغراض العرض فقط، وليس حماية أمنية.

```bash
npm ci             # تثبيت قابل للتكرار من package-lock.json
npm run build      # فحص TypeScript وبناء dist
npm run preview    # معاينة البناء محليًا
npm test           # اختبارات Vitest
```

لا توجد حاجة إلى الموقع الثابت القديم؛ أصبح index.html نقطة دخول Vite. حُذفت ملفات script.js وstyle.css القديمة بعد نقل التطبيق إلى src.

## المكتمل

- لوحة تحكم عربية متجاوبة، وتنقل إلى الشجرة والأفراد والاستيراد والإحصائيات والإعدادات.
- شجرة عمودية وأفقية من اليمين إلى اليسار، بتكبير وتحريك وخريطة مصغرة وإعادة ضبط.
- طي فرع كل شخص وفتحه، والبحث بالاسم أو المعرّف مع فتح سلسلة آبائه وتوسيط بطاقته. عند تشابه الأسماء، يُختار أول تطابق؛ استخدم ID لتحديد الفرد بدقة.
- بطاقات تعرض الحالة والأبناء المباشرين وإجمالي الذرية، مع نافذة تفاصيل وحقول مخصصة.
- جدول ببحث وتصفية وفرز وصفحات، وإضافة وتعديل وحذف مع تأكيد. المعرّف غير قابل للتعديل بعد الإنشاء لحماية المراجع. لا يُسمح بحذف أب لديه أبناء؛ انقل أبناءه إلى أب آخر أولًا. التعديلات التي تنشئ دورة أو مرجعًا مفقودًا مرفوضة.
- قراءة XLSX وXLS، ومطابقة أعمدة قابلة للتغيير، ومعاينة وأخطاء وتحذيرات برقم الصف، وتنزيل نموذج. الاستبدال يتطلب تأكيدًا صريحًا.
- إحصائيات الذرية والأحياء والمتوفين وعمق الأجيال وأعداد كل جيل وكل فرع رئيسي.
- حفظ محلي للتطوير، مع معالجة فساد التخزين أو امتلائه، واستعادة بيانات العرض بتأكيد المستخدم.
- خط Noto Sans Arabic محلي دون استدعاء Google Fonts، وحالات تحميل وفشل، وحوارات تدعم Escape وحصر التركيز.

## Excel ونموذج البيانات

العناوين الأساسية، وجميعها مطلوبة كأعمدة حتى عندما تكون قيمة الأب فارغة:

| العمود | المعنى |
| --- | --- |
| ID | معرّف نصي فريد |
| الحالة | 1 حي، 2 متوفى |
| ترتيب الشخص بين إخوته | يبدأ من 1 للأكبر، ثم 2 ثم 3… لترتيب الأبناء فقط، **وليس عمق الجيل** |
| الاسم | اسم الفرد |
| أسم الاب | اسم الأب للعرض والتحذير عند عدم مطابقته |
| يرأسه | ID الأب، فارغ للجذر |

تُقبل اختلافات الهمزات والمسافات مثل «اسم الأب». يُقبل أيضًا الاسم القديم «تسلسل الجيل» أو «ترتيب الإخوة» لعمود الترتيب. لا تظهر قيمة الترتيب في الشجرة أو التفاصيل أو جدول الأفراد؛ يمكن تعديلها في نموذج الفرد وتظهر في معاينة Excel للتحقق منها. احفظ ID و«يرأسه» بتنسيق **نص** في Excel قبل إدخالها؛ إذا حذف Excel الأصفار سابقًا فلا يمكن استعادتها تلقائيًا. نقرأ النص المعروض للحفاظ أيضًا على التنسيقات الرقمية ذات الأصفار.

تُقرأ أول ورقة عمل، بحد 10 ميجابايت و20 ألف فرد. الصف الأول للعناوين ولا تُقبل عناوين فارغة أو مكررة. الصفوف الخالية تُتجاهل مع الحفاظ على أرقام الصفوف الأصلية. الأعمدة الأخرى محفوظة كـ `customFields: Record<string,string>`، وتظهر في تفاصيل الفرد ويمكن تعديلها. القيم المخصصة نصية في هذه النسخة.

يمنع الاستيراد: المعرّفات الناقصة أو المكررة، الحالات غير الصحيحة، الأسماء الفارغة، ترتيب الإخوة غير الصحيح، مراجع الآباء المفقودة، الارتباط بالنفس، والدورات. الأسماء المكررة واختلاف اسم الأب وتعدد الجذور تحذيرات لا تمنع الاعتماد؛ المرجع دائمًا ID. يدعم التطبيق غابة من جذور مستقلة.

**مكتبة Excel:** يستخدم اسم الاستيراد `xlsx` alias إلى `@e965/xlsx@0.20.3`، وهي إعادة توزيع مجتمعية لـSheetJS CE عبر npm. اختيرت لأن خادم `cdn.sheetjs.com` محجوب في بيئة التنفيذ، وتجنبًا للإصدار القديم 0.18.5 على اسم npm الأصلي. الحزمة مثبتة بسلامة integrity في القفل. راجع مصدر التوزيعة والتراخيص ومتطلبات سلسلة التوريد قبل الإنتاج؛ يمكن استبدال alias بالتوزيع الرسمي للإصدار المدقق عند توفر الوصول. لا تُرفع الملفات إلى أي خدمة خارجية، ولا تُنفّذ وحدات ماكرو.

## منطق العلاقات والأداء

`analyzeFamily` يبني فهارس بالمعرّف وأبناء كل أب، ثم يحسب العمق بالاجتياز العرضي ومجاميع الذرية بتمرير عكسي دون recursion. الزمن O(n) للحساب الأساسي، إضافة إلى ترتيب الإخوة O(n log n) في أسوأ الحالات. `validatePeople` يكشف الدورات بمسارات تكرارية تُنجز كل معرّف مرة واحدة. إجمالي ذرية الشخص لا يشمله، بينما أحجام الفروع تشمل مؤسس الفرع. الفروع الرئيسية هي أبناء كل جذر مع ذريتهم؛ الجذر ذو الأبناء مستثنى من أعداد الفروع، والجذر المنفرد يُحسب فرعًا مستقلًا.

تُحفظ الحسابات في useMemo عند ثبات البيانات. العقد غير الظاهرة خارج مجال العرض لا تُرسم، والفروع المطوية لا تدخل في التخطيط. مكتبة التخطيط Dagre وواجهة الإحصائيات الكاملة قد تبطآن مع آلاف العقد المفتوحة؛ حد الاستيراد ليس ضمانًا لسرعة التخطيط بهذا الحجم. تحسين لاحق: Worker للتخطيط والتحليل، وعرض إحصائيات افتراضي وطي افتراضي حسب العمق.

## الخصوصية وحدود النسخة

**لا تستخدم هذه النسخة لحفظ بيانات عائلية حقيقية ولا تعتبر شاشة الدخول حماية.** التطبيق ثابت؛ لا يوجد خادم أو قاعدة بيانات أو كلمات مرور أو مصادقة إنتاجية. يستطيع مستخدم الجهاز تغيير الدور وقراءة localStorage. لا تكفي حماية المسارات أو إخفاء الأزرار في React.

لا يُرسل التطبيق البيانات للخارج ولا يحتوي تتبعًا أو رفعًا تلقائيًا. البيانات المستوردة والتعديلات تُحفظ في مفتاح `judhur-demo-family-v1` في متصفح الجهاز فقط؛ مسح بيانات المتصفح يفقدها. الجلسة التجريبية لا تُحفظ ويعاد اختيارها عند تحديث الصفحة.

قبل النشر الفعلي يلزم تنفيذ:

1. Backend وAPI وقاعدة بيانات بعلاقات أبوة سليمة ومعاملات ذرية وإعادة التحقق من الاستيراد على الخادم.
2. مصادقة آمنة عبر مزوّد موثوق أو جلسات HttpOnly/Secure/SameSite، وتفويض admin وviewer على **كل طلب** مع عزل العائلات.
3. TLS وحماية CSRF عند الحاجة وتحديد المعدل وسجل تدقيق وسياسات وصول واحتفاظ ونسخ احتياطية وحذف.
4. مراجعة سلسلة التوريد وحدود الملفات والمعالجة المعزولة وقياسات أداء واختبارات وصول وأمان.

واجهة `AuthService` جاهزة لاستبدال موائم العرض بموائم خادم. الواجهات لا تطلب كلمات مرور ولا تحتوي أسرارًا. لا يوجد رفع إلى GitHub أو نشر تلقائي ضمن هذا التنفيذ.

## التحقق المنفذ

نجح تثبيت الحزم والبناء وفحص TypeScript واختبارات Vitest، بما فيها شجرة متفرعة وأسماء مكررة وغابة جذور وسلسلة من 15 ألف جيل، وقراءة XLS/XLSX فعلية، وأرقام صفوف الأخطاء والتحقق من سلامة التخزين المحلي. كما أُجري اختبار Chromium على الحاسوب والجوال للإضافة والتعديل والحقول المخصصة والحذف، والحفظ بعد التحديث، وطي الفروع والبحث والاتجاه الأفقي، وتنزيل النموذج وإعادة استيراده بتأكيد، واستعادة العرض ودور المشاهد. تدقيق `npm audit` عند التنفيذ لم يرصد ثغرات معروفة؛ لا يمثل ذلك ضمانًا أمنيًا.

يمكن إعادة اختبار المتصفح اختياريًا عبر `scripts/browser-smoke.py` في بيئة تحتوي Python Playwright وChromium، مع خادم التطوير قيد التشغيل. يشغّل متصفحًا معزولًا ببيانات تجريبية؛ لا تستخدمه على نسخة بيانات حقيقية. يحتاج socket وتشغيل المتصفح إلى سماح بيئة التنفيذ.

```bash
# بعد تثبيت Python Playwright في بيئة اختبار منفصلة، إن لم يكن متاحًا:
APP_URL=http://127.0.0.1:5173/ CHROMIUM_PATH=/usr/bin/chromium python3 scripts/browser-smoke.py
```

لا يُثبّت سكربت المتصفح أي حزم تلقائيًا، ويحفظ لقطات مؤقتة وملف Excel في `/tmp`. اختبارات `npm test` لا تحتاج متصفحًا أو خادمًا.

## العرض والأجيال والتحريك

- العرض الافتراضي 100٪ ببطاقات أكبر وخط عربي أوضح. «عرض الكل» مخصص لرؤية الامتداد؛ قد تصبح الأسماء صغيرة في هذا الوضع.
- بطاقات الشجرة صغيرة (160 × 92 بكسل للاسم القصير) وتعرض الاسم الأول في الوسط فقط؛ تحفظ الأسماء المركبة مثل «عبد الرحمن». بطاقة التفاصيل عند الضغط تعرض الاسم الكامل، ويتصل بأسماء الآباء حتى الجذر من روابط الأبوة. تُدمج الأجزاء المتداخلة لتجنب إعادة الاسم الكامل، ويُذكر اسم العائلة المشترك في النهاية. لا تُغيّر الأسماء الأصلية المستوردة. يظل تكرار الاسم الأول بين أب وابنه موجودًا.
- ID مخفي من بطاقات الشجرة وتفاصيلها والطباعة، ويظل محفوظًا في البيانات والبحث وExcel وجدول الإدارة لسلامة الربط.
- البطاقة المختارة بالضغط أو البحث تبرز بإطار أخضر وخلفية واضحة. اضغط Escape لإغلاق التفاصيل ومشاهدة التحديد.
- «من الجيل / إلى الجيل» يحدد نطاق الأجيال الفعلية، ولا يؤثر على البيانات أو إحصائيات الذرية. البحث وفتح مسار الأسلاف يعيدان نطاق الأجيال حتى يظهر الشخص المطلوب. الجيل الأول هو الجذر، وليس ترتيب الإخوة.
- «امتداد الخطوط» يغير المسافة بين الأجيال؛ الخطوط الافتراضية أقصر وذات زوايا مستديرة. قد يطول جزء من الخط لتوصيل الفروع المتباعدة حسب التخطيط.
- «وضع التحريك»: اسحب بالماوس في الجهات الأربع، أو استخدم عجلة الماوس للتحريك وShift للحركة الأفقية. «وضع الزوم»: عجلة الماوس تكبر وتصغر، والسحب يحرك. أزرار + و− واللمس بإصبعين متاحة.
- اضغط بطاقة شخص ثم «عرض المختار وأسلافه إلى الجيل 1» لإظهار الشخص وآبائه فقط. يبقى الجذر أعلى الرسم العمودي أو يمينه في الأفقي أو أسفله في الشجرة الصاعدة. العودة للعائلة لا تحذف بيانات.

## الطباعة وPDF وExcel

«تصدير وطباعة» يتيح الأفراد الظاهرين أو جميع الأفراد، مع اختيار «من الجيل للطباعة / إلى الجيل للطباعة». حتى عند تضييق الأجيال تظل إحصائيات الذرية من العائلة كاملة؛ يظهر الاسم الكامل في التفاصيل، والاسم الأول في الشجرة وطباعتها.

- «تنزيل Excel» يصدر بيانات النطاق المختار بترتيب الإخوة وID النصي والحقول المخصصة، ويمكن إعادة استيراده. لا يصدّر صورة الرسم، وتبقى مراجع الآباء الأصلية؛ عند استيراد نطاق أجيال يبدأ بعد الجذر قد تحتاج إعادة الآباء المستبعدين حتى لا توجد مراجع مفقودة.
- أحجام الورق: A4 إلى A0، ثم 2A0 و4A0، ولوحة 100 × 200 سم، ومقاس مخصص من 100 إلى 5000 مم لكل ضلع. يحدد اتجاه الورقة الضلع الطويل أفقيًا أو عموديًا. المقاسات الكبيرة تحتاج PDF أو مطبعة تدعمها.
- «الشجرة كاملة في صفحة واحدة»: شجرة متصلة في وسط الورقة، مع الحفاظ على تجمع أبناء كل أب وترتيب الإخوة. لا يلتف الجيل إلى شبكة منفصلة. قد يصغر النص عند كثرة الأفراد.
- «صفحات عائلية دون تقسيم البطاقات»: كل بطاقة تبقى كاملة، ويظهر الأب مع أبنائه المباشرين. إذا زاد عدد الأبناء عن المساحة، يتكرر الأب في صفحات المتابعة. تُعرض ذرية كل ابن في صفحاته بوصفه أبًا، فلا يوضع ابن في صفحة منفصلة عن أبيه دون سياق. الصفحات ليست قصاصات ملصق متجاورة؛ إنها مجموعات أبوة كاملة. لا يمكن وضع فرع غير محدود بكل أجياله على ورقة صغيرة مع إبقاء حجم النص ثابتًا.
- في الصفحات العائلية تُرتّب أسماء الجيل الواحد في صف للعمودي أو عمود للأفقي لتجنب مرور الموصلات فوق البطاقات. اختر ورقًا أكبر أو نطاق أجيال أصغر لجمع أفراد أكثر. الحد 200 صفحة في عملية واحدة.
- حجم بطاقات تلقائي بحسب الورق، أو عرض يدوي من 8 إلى 80 مم. تحتوي بطاقة الطباعة الاسم فقط، دون اسم الأب أو العدادات أو ID؛ نص الحالة اختياري. قد يقل الحجم الفعلي للاحتواء، وتعرض المعاينة العرض الفعلي وحجم الخط التقريبي.
- اضغط «فتح معاينة الطباعة / PDF»، ثم «طباعة / حفظ PDF» واختر حفظ PDF أو الطابعة. استخدم مقياس 100٪، وهوامش 10 مم، وأوقف رؤوس وتذييلات المتصفح. اسمح بالنوافذ المنبثقة للموقع إذا منع المتصفح فتح المعاينة.
- الطباعة SVG متجهية بنص عربي قابل للتكبير، بخطوط Tahoma/Arial المحلية ودون رفع بيانات خارج الجهاز.

الاختبارات الإضافية في `src/tests/presentation.test.ts` تثبت تركيب الأسماء والأجيال، ومحاذاة الصفحة، وعدم قص البطاقات وبقاء الأب مع الأبناء عبر صفحات المتابعة في الاتجاهين، والمقاسات المخصصة. اختبارات المتصفح الاختيارية في `scripts/browser-smoke.py` و`scripts/browser-export-smoke.py` و`scripts/browser-tree-ux-smoke.py` تستخدم بيانات خيالية فقط وتكتب ملفات مؤقتة في `/tmp`، وتتطلب Python Playwright وChromium وخادم التطوير. اختبارات `npm test` لا تحتاج متصفحًا.

## الشجرة الصاعدة (عرض ثالث)

زر «شجرة صاعدة» يعرض الجذر في الأسفل والأبناء والأحفاد فوقه، بخطوط منحنية تتدرج في السمك وزخرفة نباتية بسيطة عند الجذر. العرضان العمودي والأفقي باقيان، ولا يتغير ارتباط الأشخاص عند التبديل. خيارات البحث والأجيال وطي الفروع والتحريك والزوم متاحة فيه. يتبع تصدير PDF الاتجاه الصاعد سواء للنطاق الظاهر أو العائلة كاملة، مع بقاء الجذر أسفل الورقة في وضع الصفحة الواحدة ومجموعات الطباعة. تبقى بيانات Excel والأسماء الأصلية دون تغيير.

## تجاور الإخوة والحالة وتوزيع الورق

- التخطيط في `src/features/tree/layout.ts` يستخدم خانات أوراق متتابعة لكل فرع، بتمريرات تكرارية دون recursion. الأبناء المباشرون الذين لا ذرية لهم يبقون بجوار بعضهم بمسافة 12 بكسل بين البطاقات، دون توزيعهم على طرفَي فروع أخرى. إذا كان لأحد الأبناء فرع كبير، تُحجز المساحة اللازمة له لمنع تداخل البطاقات. ترتيب الإخوة المحفوظ يحدد تتابعهم: 1 للأكبر في يمين الرسم العمودي والصاعد، ثم 2 و3 نحو اليسار؛ وفي الأفقي 1 في الأعلى ثم 2 و3 نحو الأسفل، ويُستخدم التخطيط نفسه للطباعة الكاملة.
- البطاقات القصيرة الآن 160 × 92 بكسل افتراضيًا. نص الحالة مخفي، ويمكن إظهاره من «إظهار نص الحالة». بطاقات المتوفين أغمق قليلًا (#e1e3dc)، دون إضافة نص إلزامي.
- تصفية الحالة: «الكل / الأحياء / المتوفون» متاحة في الشجرة والطباعة. غير المطابقين يُخفون فقط، ولا تتغير بيانات الأبوة أو إحصائيات الذرية. إذا أخفت التصفية أبًا، لا يوصل الرسم ابنه بجد آخر؛ يظهر الابن دون أب مرسوم. البحث يعيد الحالة إلى «الكل» لإظهار النتيجة.
- توجد خيارات مستقلة للحالة ونص الحالة داخل التصدير، وتبدأ بقيم العرض عند فتح الحوار. نطاق «الأفراد الظاهرون» لا يعيد إظهار أشخاص أخفتهم تصفية الشاشة؛ اختر «جميع الأفراد» لتوسيع النطاق ثم اضبط تصفية الطباعة.
- الصفحات العائلية تراعي العرض والارتفاع الفعليين للورق وهوامشه ومقياس البطاقة. تُجمع مجموعات عائلية كاملة جنبًا إلى جنب أو تحت بعضها عندما تتسع الصفحة، بدل تخصيص ورقة كاملة لكل أب تلقائيًا. يتكرر الأب في صفحات المتابعة عند الحاجة، ولا تُقص بطاقة. لكل تكرار مفاتيح رسم مستقلة حتى تبقى الموصلات ضمن مجموعته. قد يؤدي اختيار ورق أكبر إلى تقليل عدد الصفحات.
- اختبارات `compact-layout.test.ts` تشمل حالة أبناء ماجد مع فرع كبير مجاور، وترتيب الإخوة، و10 آلاف مستوى دون recursion، وحالة أب مخفي، ومقارنة A4 مع A0، وسلامة البطاقات والموصلات داخل الصفحات، وإخفاء نص الحالة وإظهاره في PDF.

## الشجرة التراثية

زر «الشجرة التراثية» يضيف عرضًا فنيًا مستلهمًا من رسومات أشجار النسب القديمة: خلفية ورقية بلون بيج، وجذع وجذور بخطوط محفورة، وأغصان خشبية متدرجة، وأسماء على أوراق. الأشخاص وروابطهم مرسومون من البيانات نفسها؛ يتغير حجم التاج وتوزيع الأوراق بحسب الفروع الفعلية، وتظهر الجذور المتعددة كأشجار مستقلة. لا تُخزّن الصورة المرجعية أو أسماء منها ضمن بيانات التطبيق.

التخطيط في `heritage.ts` يخصص نطاقًا مستقلًا لكل فرع، ويحافظ على تتابع الإخوة من اليمين لليسار، ويوزع فروع التاج مع ارتفاعات متدرجة لتقليل التشابك. العمليات تكرارية، ولا يُعتمد على عمق استدعاء الدوال. عند كثرة الأشخاص قد يصغر النص في «عرض الكل»؛ استخدم البحث أو حجم 100٪ للتحقق من الاسم، أو اطبع على ورق أكبر.

يعمل البحث وتحديد الشخص وفتح التفاصيل وطي الفروع وتصفية الحالة والأجيال والتحريك والزوم في العرض الفني. الضغط على الورقة يفتح الاسم الكامل والإحصائيات؛ يظهر على الورقة الاسم الأول فقط. بطاقات المتوفين بلون أغمق، ونص الحالة اختياري كما في العروض الأخرى. تستخدم الأشكال SVG ورسوم CSS محلية، دون صور أو خطوط أو خدمات خارجية.

يدعم PDF الخلفية والأوراق والجذع والأغصان بصيغة متجهية. للحصول على لوحة شاملة اختر «الشجرة كاملة في صفحة واحدة» وA0 أو مقاسًا مخصصًا مناسبًا. «الصفحات العائلية» تقسم إلى مجموعات أبوة كاملة بالشكل التراثي نفسه، وتكرر الأب حسب الحاجة؛ لا تمثل هذه الصفحات أجزاء متجاورة من صورة تاج الشجرة. Excel يبقى تصديرًا للبيانات.

`src/tests/heritage.test.ts` يختبر ترتيب الإخوة وكثافة الأوراق وتعدد الجذور وسلامة النصوص وحدود الجذع في الطباعة. `scripts/browser-heritage-smoke.py` يفحص العرض والبحث والتفاصيل وطباعة A0 وطي الفروع والتصفية والجوال؛ يستخدم بيانات العرض الخيالية فقط.

## طباعة النسب وملء الشاشة

يستخدم `printTree.ts` تخطيطًا مخصصًا للطباعة: بطاقة اسم بعرض منطقي 120 وارتفاع يبدأ من 34، بدل بطاقة الشاشة 160 × 92. يحتفظ كل فرع بمساحته المتصلة، وتلتقي خطوط أبناء الأب في ممر بين الأجيال. يُحفظ ترتيب الإخوة في الاتجاهات الثلاثة، ولا يُربط شخص بجد بديل إذا كان أبوه مستبعدًا. أُلغي توزيع الأفراد في شبكة أجيال لأنه يضعف قراءة النسب.

«حجم بطاقات تلقائي بحسب الورق» يختار عرضًا بين 12 و28 مم حسب الورق. ألغِه لتحديد العرض يدويًا. في الصفحة الواحدة يُحتوى الرسم كاملًا دون قص أو تشويه؛ قد يقل المقاس عن المطلوب، وتعرض المعاينة المقاس الفعلي. لعائلة كبيرة اختر ورقًا أكبر أو الصفحات العائلية للحفاظ على قراءة الأسماء. لا تتمدد المسافات لمجرد ملء الفراغ على حساب وضوح التبعية.

زر «ملء الشاشة» يخصص مساحة الشاشة للشجرة مع أدوات البحث والاتجاه والتصدير؛ تبقى التفاصيل والنوافذ متاحة. للخروج اضغط الزر أو Esc. يُستخدم ملء الشاشة الأصلي عند دعمه، وإلا عرض يغطي نافذة الموقع. يعود موضع العرض السابق عند الخروج.

`src/tests/print-tree.test.ts` يختبر شجرة كبيرة عبر ثمانية أجيال في الاتجاهات الثلاثة، وترتيب الأبوة وعدم تداخل البطاقات، وبقاء الأفراد والموصلات، وحجم الطباعة التلقائي واليدوي. `scripts/browser-name-print-fullscreen-smoke.py` يفحص الأسماء فقط في PDF، وملء الشاشة والبحث والتفاصيل والتصدير والخروج والجوال. `scroll-lock.test.ts` يتحقق من استعادة التمرير عند إغلاق النوافذ بترتيبات مختلفة.

التصميم التراثي يحتفظ بنقاط تفرع متصلة وأوراق جانبية وجذع يتصل بالتفرع؛ تبقى الزخارف خارج البيانات والإحصائيات. `pageLayout.ts` يوسّع الرسم الفني فقط. ملفات المستخدم المرفقة لا تُنسخ إلى المستودع أو تُرفع إلى GitHub.
